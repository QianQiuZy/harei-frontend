# Harei Music Design System

## 1. Atmosphere & Identity

The existing Harei site remains a playful illustrated personal space. Music surfaces add a compact editorial songbook layer: warm paper, dark ink, coral emphasis, and small lemon/blue accents. The public catalog feels collectible and musical; the management area uses the same visual language with denser operational layouts.

## 3. Typography

| Level | Size | Weight | Line height | Usage |
|---|---:|---:|---:|---|
| Display | `clamp(2.35rem, 5vw, 3.6rem)` | 800 | 1.1 | Public title |
| H1 | `2rem` | 800 | 1.2 | Admin page title |
| H2 | `1.35rem` | 700 | 1.3 | Panels/dialog sections |
| Body | `1rem` | 400 | 1.6 | Forms and content |
| Body small | `0.875rem` | 400 | 1.5 | Metadata |
| Caption | `0.75rem` | 700 | 1.4 | Labels and overlines |

- Sans: self-hosted `"Noto Sans SC Variable"`, then `"Source Han Sans SC", "Microsoft YaHei", sans-serif`
- Serif: self-hosted `"Noto Serif SC Variable"`, then `"Source Han Serif SC", "Songti SC", SimSun, serif`
- Serif is reserved for song titles and editorial headings.

## 4. Spacing & Layout

The base unit is 4px. Music spacing uses 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, and 96px steps.

- Public catalog max width: 1180px.
- Management shell max width: 1440px.
- Public cards remain one column at all breakpoints.
- Management surfaces keep their desktop layout and are not optimized for narrow viewports; the authentication page is the exception and reuses the shared responsive login primitive.
- Primary content must not create horizontal scrolling at 375px.

## 5. Components

### Music Button
- Variants: ink, coral, subtle, destructive.
- States: default, hover, active, focus-visible, disabled, loading.
- Minimum touch target: 42px; destructive actions require an explicit confirmation.

### Song Card
- Structure: title/artist metadata cluster plus latest-listen action.
- States: default, hover/focus, loading skeleton, archived in management views.
- Motion: 160–180ms transform/background only.

### Filter Panel
- Structure: labeled native controls, search-mode toggle, reset action, active chips.
- Responsive: four-column controls collapse to two columns, then one column at mobile.
- Accessibility: every control has an explicit label and visible focus.

### Song Dialog
- Structure: close action, editorial heading, metadata chips, notes, chronological history.
- States: loading, loaded, empty, error.
- Accessibility: native dialog semantics, focus restoration, Escape close, body scroll lock.

### Management Shell
- Structure: compact header/navigation and a single scroll-owning content area.
- Public AppShell background/sidebar are excluded.
- Navigation exposes dashboard, songs, audit, public preview, and logout.

### Management Form
- Structure: labeled field grid, version/conflict notice, save/archive controls, performance list.
- States: clean, dirty, saving, saved, validation error, version conflict.
- Responsive behavior: none; management fields and actions retain the desktop layout.
- Song and performance source keys are generated by the service and are never editable fields. BV/live identifiers are derived from URL fields.

### Performance Import
- Structure: template-download action, XLSX file action, and inline multiline result notice on the song management page.
- Template: `导入数据` captures song title/date/live title/clip URL; `歌曲列表` provides the current exact-match vocabulary.
- States: idle, downloading, importing, success count, row-specific validation failure.

### Catalog Identity
- The title lockup uses the supplied `harei-singing.gif` in a fixed 96px framed identity tile, reduced to 76px on mobile.

### Back to Top
- A 50px fixed circular ink button appears at 20px from the right and bottom once the catalog heading leaves the viewport.
- Hidden state uses opacity plus `scale(.88) translateY(12px)` with pointer events disabled; visible state restores full scale and smooth-scrolls to the document top.
- `prefers-reduced-motion` changes scrolling and transitions to effectively instant behavior.

## 6. Motion & Interaction

| Type | Duration | Easing |
|---|---:|---|
| Micro | 160ms | ease-out |
| Standard | 240ms | ease-in-out |
| Dialog | 360ms | `cubic-bezier(0.2, 0.9, 0.28, 1.18)` |

Only `transform`, `opacity`, and color/background transitions are animated. `prefers-reduced-motion` disables non-essential motion.

## 7. Depth & Surface

The strategy is mixed but restrained: thin ink-alpha borders define compact cards; shadows are reserved for dialogs and the reference identity image. Management panels use borders and tonal shifts rather than repeated heavy shadows.

## 8. Accessibility Constraints & Accepted Debt

- Target WCAG 2.2 AA: 4.5:1 body contrast, 3:1 large text, visible focus on all controls.
- Full keyboard reachability for filters, dialogs, navigation, forms, and destructive confirmations.
- Loading/error/saved states use `aria-live` where appropriate.
- Public mobile primary actions remain at least 42px high.
- Accepted debt: the existing non-music site has no unified token system; this contract governs new music surfaces without restyling unrelated pages.
